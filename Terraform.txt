Day 1

Terraform is a open source infrastructure as a code tool by using that we can create resources in cloud providers.

terraform init is used to initialize a Terraform project by downloading providers and preparing the working directory.
 
Terraform plan is a dry run that shows the resources to be created, updated, or deleted, allowing us to verify the changes before provisioning the infrastructure.
 
terraform apply applies the execution plan and provisions or modifies the infrastructure

Terraform state file is used to keep track of the resources that terraform manages. It stores the current state of infrastructure that plan and apply changes accurately

5. Terraform Code Organization = Instead of writing everything in a single main.tf file, we split the configuration into multiple files such as provider.tf, variable.tf, main.tf, and output.tf. This is called Terraform code organization or modular file structure. It improves readability, maintainability and collaboration

6. Input Variable = Input variables are parameters that allow us to pass values into a Terraform configuration. They make the code reusable, flexible and easier to maintain by avoiding hardcoded values.

7. Output Variables = It is used to display information about the resources that terraform creates.

Created variable.tf. In this variable file we not mention the values in the default section, in this case when the user only need to give the input value when enter the terraform plan command.

provider.tf
-----------

  region = "us-east-1"
}

-------

Day 3

Modules
----------

A Terraform module is a reusable collection of Terraform configuration files used to create and manage a set of infrastructure resources. Modules help reduce code duplication, improve organization and make infrastructure easier to maintain.

Example : Instead of writing EC2 instance code multiple times, we can create an EC2 module once and reuse it whether needed by passing different input variables.

In the GitHub created one repo = Terraform
Created directories in the repo = mkdir -p /Modules/ec2-instance
Entering into the ec2-instance directory
In this path create the file provider.tf, main.tf, variable.tf, output.tf.
Then if any development team want to create infrastructure, they just create the simple main.tf file with the values(AMI, instance_type) and in the source they mentioned the GitHub path.

main.tf
-------

provider "aws" {
  region = "us-east-1"
}
 
module "ec2-instance" {
  source                 = "git::https://github.com/CNaveen0101/Terraform.git"  #We can mention our file path
  ami                    = "ami-091138d0f0d41ff90"
  instance_type          = "t2.micro"
  key_name               = "RD key"
  subnet_id              = "subnet-015f6441357b3bf93"
  vpc_security_group_ids = "sg-09e8f22937eb53ec4"
}

Day 5 - Provisioners

In Terraform, provisioners are used to execute scripts or commands on a local machine or on a resource after it is created (or before it is destroyed).

Types of Provisioners

1. file

Copies files or directories to a remote resource.

Eg
provisioner "file" {
  source      = "app.conf"
  destination = "/etc/app.conf"
}

2. local-exec

local-exec is a Terraform provisioner that executes commands on the machine where Terraform is running, after a resource is created or destroyed

Eg:
provisioner "local-exec" {
  command = "echo Resource created!"
}

3. remote-exec
Runs commands on the resources which we created 

Eg:
provisioner "remote-exec" {
  inline = [
    "sudo apt update",
    "sudo apt install -y nginx"
  ]
}

Day 6 - Workspace

Terraform workspace is a feature used to manage multiple environments using the same Terraform configuration. Each workspace has its own separate state file, which helps isolate infrastructure resources between environments such as development, testing, and production.

Creating workspaces commands

	terraform workspace new dev
	terraform workspace new stage
	terraform workspace new prod

Moving workspace command

	terraform workspace select dev

Checking the current workspace command

	terraform workspace show

Creating files 

	dev.tfvars
	stage.tfvars
	prod.tfvars

terraform apply -var-file=prod.tfvars
